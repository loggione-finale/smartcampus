# 0009 – Test: xUnit sui database reali

- Data: 26/10/2026
- Stato: accettata

## Contesto
Le slide chiedono prove che distinguano un difetto da un'ipotesi e che concorrenza e persistenza siano provate sul database reale.

## Decisione
- **xUnit** per tutti i servizi.
- **Test di integrazione sui database reali** di Docker Compose, su database dedicati (`bookings_test`, `users_test`, `spaces_test`), in locale e in CI.
- **Test di coerenza dei dati sintetici** senza database (`tests/SmartCampus.SyntheticData.Tests`).
- **Prove di guasto** per ogni servizio (#66) e prove manuali registrate in [evidence](../evidence/README.md) con esito atteso e osservato.

## Alternative considerate
- **Provider in memoria di EF Core** per tutto: veloce, ma non prova i vincoli di esclusione né la concorrenza; resta solo dove non conta il database (per esempio il seed degli utenti).
- **Testcontainers:** il PostgreSQL di Docker Compose è già un database reale.

## Conseguenze
- Più facile: i vincoli si provano davvero (anche con il vincolo tolto, la prova fallisce).
- Più difficile: i test sullo stesso database possono interferire tra loro. Lezioni dello Sprint 1: niente `TRUNCATE` in parallelo (#143), dati univoci per esecuzione (#154).
- Il parallelismo dei test di Bookings è disattivato: la suite è più lenta ma stabile.
